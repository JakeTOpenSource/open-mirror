Six containers in a row, numbered 1 to 6; 1 is upstream, 6 is downstream. Each has a whole-number amount that is never negative, a fixed capacity C, an upper trigger U and a lower trigger D with D < U <= C, and one of two states, NORMAL or ELEVATED. All start NORMAL. There is one global limit G and one running tally LOST, which starts at 0. The process runs exactly 5 periods. Each period has five steps, always in this order, and each step finishes for all six containers before the next starts. Step 1 (intake): each container's amount rises by that period's table entry for it; capacity is not enforced, so an amount may exceed capacity. Step 2 (spill-over): handle containers one at a time in order 1, 2, 3, 4, 5, 6; if a container's amount is above its capacity, the excess (amount minus capacity) is added to container n+1 and the container is set exactly to capacity; excess from container 6 is added to LOST; because of the order, excess arriving in a container is there before that container is handled, so excess can cascade down the line in the same step. Step 3 (state check), on amounts after spill-over: NORMAL with amount >= U becomes ELEVATED; ELEVATED with amount <= D becomes NORMAL; every other case, including any amount strictly between D and U, keeps its state; record every change as (period, container, old state, new state); a container changes at most once per period. Step 4 (release): first compute every container's release from its amount at the start of this step, NORMAL = floor(amount/4), ELEVATED = floor(amount/2), all six computed before anything changes; then apply all at once: every container loses its own release; a NORMAL container's release is added to LOST; an ELEVATED container's release is added to container n-1, except container 1's, which is added to LOST; capacity is not enforced here, so a container may sit above capacity, corrected only at the next period's spill-over, and never if this happens in period 5. Step 5 (global reset): sum all six amounts; if the sum is strictly greater than G, every amount becomes floor(amount/2), every removed amount is added to LOST, and the period is recorded as a reset period; if the sum is equal to G or less, nothing happens. After period 5 the output is: each container's final amount, in order 1 to 6; each final state, in order 1 to 6; the complete list of state changes as (period, container, old state, new state); the periods in which a reset happened; the final LOST; and the balance check, (sum of starting amounts) + (sum of all intake amounts) = (sum of final amounts) + LOST.
