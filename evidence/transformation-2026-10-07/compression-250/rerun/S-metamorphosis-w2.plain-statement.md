Six units in a row, numbered 1 to 6; 1 is first (upstream), 6 is last (downstream). Each unit holds an amount that is a whole number and never negative, and has a fixed capacity, an upper trigger and a lower trigger (lower below upper, upper at most capacity), and one of two states: a resting state or a raised state. All units start in the resting state. There is one global limit, 38, and a loss tally that starts at 0. The process runs exactly 5 rounds. Each round has five steps in a fixed order, and each step is finished for all six units before the next step starts. Step 1: each unit's amount goes up by that round's table value for that unit; capacity is not enforced, so an amount may end above capacity. Step 2: handle units one at a time in order 1, 2, 3, 4, 5, 6; if a unit's amount is above its capacity, the excess (amount minus capacity) is added to the next unit downstream and the unit is set to exactly its capacity; excess from unit 6 is added to the loss tally; because handling is in order, excess from one unit arrives before the next unit is handled, so it can push that unit over capacity in the same step, and so on down the row. Step 3: using the amount after step 2, a resting unit at or above its upper trigger becomes raised; a raised unit at or below its lower trigger becomes resting; in every other case the state stays as it was (in particular, an amount strictly between the triggers keeps the current state); each change is recorded as (round, unit, old state, new state); a unit changes at most once per round. Step 4: first compute every unit's amount from its amount at the start of this step: resting unit, floor(amount / 4); raised unit, floor(amount / 2); compute all six before changing anything, then apply all at once: each unit loses its own computed amount; a resting unit's amount goes to the loss tally; a raised unit's amount is added to the unit immediately upstream (unit n-1); if unit 1 is raised, its amount goes to the loss tally; capacity is not enforced, so a unit may be above capacity afterwards, and that is corrected only in the next round's step 2, never if it happens in round 5. Step 5: add up all six amounts; if the total is strictly greater than 38, every unit's amount becomes floor(amount / 2), all removed amounts go to the loss tally, and the round is recorded as a reset round; if the total is 38 or less, nothing happens. After round 5 the output is: each unit's final amount in order 1 to 6; each unit's final state in order 1 to 6; the complete list of state changes as (round, unit, old state, new state); the list of rounds in which a reset happened; the final loss tally; and the balance check, (sum of starting amounts) + (sum of all table amounts) must equal (sum of final amounts) + loss tally. Data, units 1 to 6: capacity 10, 8, 12, 6, 9, 7; upper trigger 7, 6, 9, 5, 7, 5; lower trigger 3, 2, 4, 2, 3, 2; starting amount 3, 6, 6, 2, 2, 1; global limit 38. Table, rows are rounds 1 to 5, columns units 1 to 6: round 1: 0, 6, 3, 5, 3, 3; round 2: 4, 2, 0, 1, 1, 7; round 3: 4, 4, 3, 0, 0, 6; round 4: 7, 6, 7, 1, 3, 0; round 5: 0, 6, 6, 3, 3, 0.
