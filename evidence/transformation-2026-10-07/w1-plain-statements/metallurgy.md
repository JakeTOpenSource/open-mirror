Mode: explanation mode, step 1 only (plain statement), per the Open Mirror procedure. Six units in a line, numbered 1 to 6; 1 is upstream, 6 is downstream. Each unit holds a whole-number amount that is never negative, has a fixed capacity, an upper trigger and a lower trigger (lower < upper <= capacity), and is in one of two states, the resting state or the raised state. All units start in the resting state. There is one global limit, 38, and one running loss tally that starts at 0. The process runs exactly 5 rounds. Each round has five steps in a fixed order, and each step finishes for all six units before the next step starts. Step 1: add that round's input amount to each unit, from the input table. Capacity is not enforced here, so a unit may end up above capacity. Step 2: handle units one at a time in order 1, 2, 3, 4, 5, 6. If a unit is above capacity, the excess (amount minus capacity) is added to the next unit downstream and the unit is set to exactly its capacity. Excess from unit 6 goes to the loss tally. Because of the order, excess from one unit arrives before the next unit is handled, so it can push that one over in the same step, and so on down the line. Step 3: using the amount after step 2, a resting unit at or above its upper trigger becomes raised, and a raised unit at or below its lower trigger becomes resting. Otherwise the state does not change; a unit between the triggers keeps its state. Record every change as (round, unit, old state, new state). A unit changes at most once per round. Step 4: first compute every unit's outflow from its amount at the start of this step: resting gives floor(amount / 4), raised gives floor(amount / 2). Compute all six before changing anything, then apply all at once: each unit loses its own outflow; a resting unit's outflow goes to the loss tally; a raised unit's outflow is added to the unit immediately upstream, except that unit 1's outflow, if raised, goes to the loss tally. Capacity is not enforced here; a unit may exceed capacity after receiving, which is corrected only in the next round's step 2, and never if it happens in round 5. Step 5: add up all six amounts. If the total is strictly greater than 38, every unit becomes floor(amount / 2) and every removed amount goes to the loss tally; record that a reset happened this round. At 38 or less, nothing happens. Output after round 5: each unit's final amount in order 1 to 6; each unit's final state in order 1 to 6; the full list of state changes as (round, unit, old, new); the rounds in which a reset happened; the final loss tally; and the balance check: sum of starting amounts plus sum of all inputs must equal sum of final amounts plus the loss tally.
