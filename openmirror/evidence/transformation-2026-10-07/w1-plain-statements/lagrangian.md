Six positions in a line, numbered 1 (upstream) to 6 (downstream). Each position holds a whole-number amount that is never negative, and has a fixed capacity C, an upper trigger U and a lower trigger D, with D < U <= C. Each position is in one of two states, resting or raised, and all start resting. There is one global limit G = 38 and one running loss tally, which starts at 0. Data: capacity C for positions 1 to 6 = 10, 8, 12, 6, 9, 7. Upper trigger U = 7, 6, 9, 5, 7, 5. Lower trigger D = 3, 2, 4, 2, 3, 2. Starting amounts = 3, 6, 6, 2, 2, 1. Input table (rows are cycles 1 to 5, columns are positions 1 to 6): cycle 1: 0, 6, 3, 5, 3, 3; cycle 2: 4, 2, 0, 1, 1, 7; cycle 3: 4, 4, 3, 0, 0, 6; cycle 4: 7, 6, 7, 1, 3, 0; cycle 5: 0, 6, 6, 3, 3, 0. The process runs exactly 5 cycles. Each cycle has five steps in a fixed order, and each step finishes for all positions before the next begins. Step 1: each position's amount goes up by that cycle's table entry for it; capacity is not enforced, so an amount can exceed capacity. Step 2: handle positions one at a time in order 1 to 6; if a position's amount is above its capacity, the excess (amount minus capacity) is added to the next position downstream and the position is set to exactly its capacity; excess from position 6 goes to the loss tally. Because handling is in order, excess from one position arrives before the next is handled, so it can push that one over in the same step, cascading down the line. Step 3: using amounts after step 2, a resting position whose amount is greater than or equal to U becomes raised; a raised position whose amount is less than or equal to D becomes resting; otherwise the state does not change (between D and U the state is kept). Record each change as (cycle, position, old state, new state). A position changes at most once per cycle. Step 4: first compute every position's amount to move from its amount at the start of this step: resting gives floor(amount/4), raised gives floor(amount/2); compute all six before changing anything, then apply all at once. Every position decreases by its own amount; a resting position's amount goes to the loss tally; a raised position's amount is added to the position immediately upstream (n-1), and position 1's, if raised, goes to the loss tally. Capacity is not enforced here; a position can be above capacity after receiving, corrected only at the next cycle's step 2, and never if it happens in cycle 5. Step 5: add up all six amounts; if the total is strictly greater than G (38), every amount becomes floor(amount/2), everything removed goes to the loss tally, and the cycle is recorded as a reset cycle; if the total is 38 or less, nothing happens. After cycle 5 the output is: each position's final amount in order 1 to 6; each position's final state in order 1 to 6; the complete list of state changes as (cycle, position, old, new); the list of cycles in which a reset happened; the final loss tally; and the balance check: sum of starting amounts plus sum of all table entries must equal sum of final amounts plus the loss tally.
