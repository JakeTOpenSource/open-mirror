Mode: explanation mode (step 1 only, run on the engineer's process). Plain statement: Six positions in a row, 1 to 6; 1 is upstream, 6 downstream. Each holds a whole, never-negative amount, and has a fixed capacity, an upper trigger and a lower trigger (lower < upper <= capacity), and one of two states, resting or raised. All start resting. One global limit (38) and one running loss tally (starts at 0). Exactly 5 cycles, each with five steps in fixed order; each step finishes for all six positions before the next begins. Step 1: each position's amount rises by that cycle's table entry for it; capacity is not enforced, so an amount may exceed capacity. Step 2: handle positions one at a time in order 1 to 6; if amount > capacity, the excess goes into position n+1 and the amount is set to capacity; excess from 6 goes to the loss tally; because of the order, excess arriving from n can push n+1 over capacity, cascading down the line. Step 3: using amounts after step 2, a resting position with amount >= upper trigger becomes raised; a raised position with amount <= lower trigger becomes resting; otherwise state is unchanged (between the triggers it keeps what it had); record each change as (cycle, position, old, new); at most one change per position per cycle. Step 4: first compute all six amounts from the amounts at the start of this step: resting = floor(amount/4), raised = floor(amount/2); then apply all at once: each position loses its own amount; a resting position's amount goes to the loss tally; a raised position's amount goes to position n-1, except position 1's, which goes to the loss tally. Capacity not enforced; overfill is corrected only at the next cycle's step 2, and never if it happens in cycle 5. Step 5: sum all six; if strictly greater than the global limit, every amount becomes floor(amount/2), all removed units go to the loss tally, and the cycle is recorded; if equal or less, nothing. Output after cycle 5: final amounts 1 to 6; final states 1 to 6; full list of state changes (cycle, position, old, new); cycles in which the reset fired; final loss tally; balance check: sum of starting amounts + sum of all table entries = sum of final amounts + loss tally.
