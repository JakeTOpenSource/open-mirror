Six positions in a line, 1 to 6; position 1 is upstream (first), position 6 downstream (last). Each position holds a whole-number amount, never negative, and has a fixed capacity C, an upper trigger U and a lower trigger D, with D < U <= C, and a state that is either resting or raised. All positions start in the resting state. There is one global limit G and one running loss tally that starts at 0. The run lasts exactly 5 cycles; each cycle has five steps in a fixed order, and each step finishes for all six positions before the next step starts. Step 1 (input): each position's amount increases by that cycle's amount for that position from the input table; capacity is not enforced, so an amount may exceed capacity. Step 2 (carry-forward): positions are handled one at a time in order 1, 2, 3, 4, 5, 6; if a position's amount is above its capacity, the excess (amount minus capacity) is added to the next position downstream and the position is set to exactly its capacity; excess from position 6 is added to the loss tally; because handling is in order, excess arriving from position n is in position n+1 before n+1 is handled, so it can cascade down the line. Step 3 (state check), on amounts after carry-forward: a resting position with amount >= U becomes raised; a raised position with amount <= D becomes resting; in every other case the state is unchanged (a position between D and U keeps its state); record each change as (cycle, position, old state, new state); a position changes at most once per cycle. Step 4 (outflow): first compute every position's amount from its amount at the start of this step, all six before changing anything: resting gives floor(amount/4), raised gives floor(amount/2); then apply all six at once: each position decreases by its own amount; a resting position's amount goes to the loss tally; a raised position's amount is added to the position immediately upstream (n-1); a raised position 1's amount goes to the loss tally. Capacity is not enforced here; a position may exceed capacity after receiving from downstream, corrected only at the next cycle's carry-forward step, and never if this happens in cycle 5. Step 5 (global reset): sum the six amounts; if the total is strictly greater than G, every position becomes floor(amount/2) and everything removed is added to the loss tally, and the cycle is recorded as a reset cycle; if the total is equal to G or less, nothing happens. Output after cycle 5: each position's final amount in order 1 to 6; each final state in order 1 to 6; the complete list of state changes as (cycle, position, old, new); the list of cycles in which a reset happened; the final loss tally; and the balance check: sum of starting amounts plus sum of all input amounts must equal sum of final amounts plus the loss tally.
